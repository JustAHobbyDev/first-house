# Pre-birth boundary

**No canonical First House has been born.** This repository constructs software
for a possible later institution. Development actors are expressly disposable
fixtures, not persons within the project's mythology: no human commission has
constituted them as canonical members, no ratified canon binds them as such, and
their records are isolated test history. A fixture's `active` lifecycle means it
can participate in a software test; it does not mean canonical awakening.

The handoff does not supply a completed birth rite or ratified creation myth.
This implementation does not invent one. Birth would require an explicit Regent
decision to constitute a canonical institution under reviewed canon and begin
its canonical Genesis Record. Its exact rite and meaning remain for the Regent
to establish; calling a constructor or running the demo cannot substitute for it.

Before any future canonical Genesis Record, review at least:

- The ratified myth, covenant, charter, office definitions, and birth authorization.
- Canonical membership, identity, consent/commission, tenure, and amendment rules.
- Independent testimony and appeal access outside House control; the Witness With
  No Seat and the Seat of Seats cannot be established by internal runtime labels.
- Operational persistence, independently retained checkpoints, backup and recovery,
  access control, and separation of constitutional authority from external content.
- Context provenance, provider behavior, capability policy, and authorized effects.
- Neighbor relations and commitment acceptance, commercial receipts and offerings,
  compute provision and dormancy, with no money-to-favor or money-to-compute rule.
- A separate canonical store with an explicit genesis procedure. Do not relabel,
  import, or promote the disposable development event stream as canonical history.

The current runtime accepts only development metadata and `dev:` identities. It
has no birth command, live model SDK, email, browsing, shell capability, payment
execution, wallet, autonomous canon amendment, death/resurrection semantics,
reproduction, fission, inheritance, or moral scoring. The future Witness/Seat
boundary is represented in context and typed testimony/authority concepts, but
no final heroic identity or canonical occupancy is claimed.

The Regent's provision is not wages; offerings purchase neither tokens nor favor.
Compute exhaustion can be represented only as dormancy. The bootstrap provides
the transition rule but does not implement actual token metering or provisioning.
